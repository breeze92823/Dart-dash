## The game
A dart-hunting tycoon. The hub is a flat checker-grass plateau; its north edge is the **yellow aiming band**. Stepping onto the band from the hub enters aim mode (first person, blowpipe view model): mouse (pointer lock) / touch drag aims, click or SHOOT fires, right-click or SCOPE opens the scope (- / + / wheel zoom), E darts, Q weapons, Alt frees the mouse, X / BACK leaves. Below the band a grass slope drops 16 m to the **lane**, which holds all five areas one after another (Meadow, Marsh, Forest, Mountain, Volcano, 70 m each; the Volcano ends at a terraced cliff face). Each area roams its own six Index animals; a green barrier at the far end of each area opens once you own the gun for the next one, and that gun's range reaches that area from the band. The normal view distance is short (far areas are not drawn); scoping in opens it to the weapon's range. A dart hit puts an animal to sleep (multi-hit for tougher ones) with a countdown ring; the player runs down, picks it up (E / tap the prompt), carries it overhead (heavy animals slow you) and steps into their fenced **base** before it wakes. Pen animals earn $/s with "+N $" pops. Timed events spawn a special animal (Legendary Boar, Rainbow Heron...) with a banner and a wooden "Next Event" sign. Three NPC hunters do the same loop (their sleeping catches can be stolen) and fill the leaderboards.
- **Money only**: every shop, boost, upgrade and cosmetic costs $ (see the workspace CLAUDE.md rule); the battle pass is a free track.
- All art is procedural (stud-plated boxes, canvas textures); all audio is synthesised (WebAudio); no asset files besides `public/avatars/player.glb`.

Three.js (vanilla) + Vite + Rapier (`@dimforge/rapier3d-compat`, top-level await, hence `build.target: 'es2022'`). Fonts: Fredoka + Luckiest Guy (index.html).

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.

## Multiplayer + bases
- Hub layout, north to south: the band; the front row (Next Event sign, events board, Dart Shop, gift; z -38..-22); the 6 bases (`config.js` `BASES` / `PLOT`, 3 columns x 2 rows, z -22..50): an 8 m strip with the owner's treadmill and pen-upgrade sign, then a 31 x 28 m fenced pen with its gate in the NORTH fence (toward the band), 6.5 m aisles between the columns; the town (`HUB.town`, z 52..98: the other shop stalls, portal) and the leaderboards on the south wall. `world/hub.js` builds every base (`live.bases[i]`: marker, signs, mill, zones tagged with `slot`).
- `game/base.js` drives the LOCAL player's base (`setSlot(n)` when the server assigns one; main.js `syncSlot` also moves the spawn there via `player.setSpawn`). `game/remoteBases.js` fills the other slots from the roster (pen animals from `base`, signs, the owner's treadmill running while `tm`), FREE BASE when empty. `game/treadmillFx.js` animates any treadmill. `game/remotePlayers.js` draws the other players (Bloxity look from `avatar` = ids + proportions only, name tag, pose easing, carry / aim poses, emotes, chat bubbles).
- `net.js`: `net.slot`, `net.players(fn)` (roster read in place each frame), `sendPose` (~10/s: x y z yaw speed tm aim carry), `sendBase` (animals, pen level, treadmill level, steps, cosmetics), `sendAvatar`, `sendEmote`, `claimAdReward`. Join options carry the Bloxity token, pose and look; `?roomId=` (invite) is tried first, then the matchmaker with backoff (`NET.joinWindow`).
