## The game
A dart-hunting tycoon. The hub is a flat checker-grass plateau; its north edge is the **yellow aiming band**. Stepping onto the band from the hub enters aim mode (first person, blowpipe view model): mouse (pointer lock) / touch drag aims, click or SHOOT fires, right-click or SCOPE opens the scope (- / + / wheel zoom), E darts, Q weapons, Alt frees the mouse, X / BACK leaves. Below the band a grass slope drops to the **lane** (meadow, pond, trees, hay, fences) where animals roam. A dart hit puts an animal to sleep (multi-hit for tougher ones) with a countdown ring; the player runs down, picks it up (E / tap the prompt), carries it overhead (heavy animals slow you) and steps into their fenced **base** before it wakes. Pen animals earn $/s with "+N $" pops. Timed events spawn a special animal (Legendary Boar, Rainbow Heron...) with a banner and a wooden "Next Event" sign. Three NPC hunters do the same loop (their sleeping catches can be stolen) and fill the leaderboards.
- **Money only**: every shop, boost, upgrade and cosmetic costs $ (see the workspace CLAUDE.md rule); the battle pass is a free track.
- All art is procedural (stud-plated boxes, canvas textures); all audio is synthesised (WebAudio); no asset files besides `public/avatars/player.glb`.

Three.js (vanilla) + Vite + Rapier (`@dimforge/rapier3d-compat`, top-level await, hence `build.target: 'es2022'`). Fonts: Fredoka + Luckiest Guy (index.html).

- `npm run dev` / `npm run build`. The preview config is `dart-dash` in `C:\ThreeJS\Dart-dash\.claude\launch.json` (port 5231, `VITE_DEV_MODE=true`). Deploy: `.github/workflows/deploy.yml` uploads `dist/` to Bloxity Hosting.
- All tunables are in `src/config.js`: base sections (identity, `PHYSICS`, look, graphics presets, `CAMERA`, rig/`ANIM`) plus the game: `STUD`, `HUB`, `BAND`, `SLOPE`, `LANE`, `BARRIER`, `BASE`, `RARITIES` (common..mythic), `WORLDS` (meadow, marsh, forest, mountain, volcano: mult, $ unlock, lane tint, Index reward), `ANIMALS` (generated from per-world `ROSTER` rows, one per rarity, + the `SEASON` (Halloween) roster; each reuses one of 11 voxel `MODELS` with a `recolor` map and `scale`), `MUTATIONS` (shiny, golden, diamond, rainbow, void) + `MUTATION_MILESTONES`, `LANE_ANIMALS`, `EVENTS` (`pick` / `season` by rarity), `WEAPONS` (6, Armory order = rank; scope zooms, `SPREAD`; owning one opens the worlds whose `WORLDS[w].weapon` it is or ranks above), `DARTS` (classic: sleep s + bonus damage; special: Hibernation and the mutation darts that turn what they put to sleep Golden / Diamond / Rainbow / Void), `DART_SHOP` (restock, free restock, instant restock for $, Big Quiver, x10 packs), `FREE_DARTS`, `AIM`, `PEN` (active slots + storage), `TREADMILL`, `START`, `CARRY`, `BOOSTS`, `TREAD_BOOST`, `GIFT`, `OFFLINE`, `BATTLE_PASS`, `GOALS`, `COSMETIC_RARITY`, `COSMETICS` (7 trails whose `speed` multiplies treadmill steps; 24 auras with a `style` (flames / storm / sparkles / orbit) and `get` (shop $ / Index mutation / world Index)), `SKINS` (30 weapon skins: palette + `deco` + dart + scope look, 15 sold in the Skin Shop, the rest earned), `PLAYTIME` (12 rewards; `at` must match the backend's `PLAYTIME_STEPS`), `GAME_SETTINGS`, `SERVER_URL`/`NET`, `BOTS`, `AUDIO`, `POSES`.

## Mobile & responsive (required for every change)
The game must play on phones and tablets (portrait and landscape) as well as desktop. Treat a feature as unfinished until it works on touch and on a small screen.
- **Input**: every action needs a touch path, not just a key. Use Pointer Events (`pointerdown/move/up`, check `e.pointerType`), never mouse-only events. Layout (implemented in `src/touch.js`): left-thumb virtual joystick -> `inputState.move`, right-side drag -> `inputState.look`, on-screen buttons for jump/sprint/mode/etc., pinch -> `inputState.zoom`. Everything still feeds `inputState` in `src/input.js` so game code stays input-agnostic. Pointer lock does not exist on touch; never rely on it.
- **Detection**: decide touch UI with `matchMedia('(pointer: coarse)')` / `navigator.maxTouchPoints`, not the user agent. Show touch controls only on coarse pointers; a device can have both.
- **Layout/UI**: HUD and menus use relative units (`%`, `vw/vh`, `dvh`, `clamp()`) and flexbox/grid, no fixed pixel layouts. Tap targets >= 44px. Respect notches with `env(safe-area-inset-*)` (viewport already has `viewport-fit=cover`). Text readable at 360px width. No hover-only interactions. Add `touch-action: none` on the canvas and game controls so the browser does not scroll/zoom.
- **Resize/orientation**: anything sized to the screen (camera aspect, renderer, HUD) must react to `resize` (covers orientation changes). Use `visualViewport` where the on-screen keyboard or browser bars matter.
- **Performance**: mobile GPUs are weak. Respect the `graphics_quality` presets in `src/config.js` (cap DPR, shadow map size, draw distance); default to a lower preset on coarse-pointer devices. Avoid per-frame allocations; keep draw calls and texture sizes low.
- **Testing**: check every UI/input change at a phone viewport (e.g. 375x812 and landscape 812x375) with touch emulation, plus desktop, before calling it done.
